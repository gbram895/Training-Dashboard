# Training Dashboard

A personal training dashboard for tracking workouts, goals, and Apple Health
metrics. Works as an installable app on your phone (PWA) and as a regular web
app on desktop.

## Stack

- **client/** — React + Vite + TypeScript, mobile-first responsive UI,
  installable PWA
- **server/** — Express + TypeScript API, serves the built client in
  production
- **Database** — PostgreSQL via Prisma ORM

## Features

- Email/password auth
- Log workouts (run, ride, strength, swim, walk, other) with duration,
  distance, notes, and per-exercise sets/reps/weight for strength sessions
- Dashboard with weekly training volume chart and recent workouts
- Goals with progress tracking
- Apple Health sync — a `POST /api/health/import` endpoint (protected by a
  `SYNC_API_KEY` shared secret) ingests daily
  [Health Auto Export](https://www.healthexportapp.com/) JSON and aggregates
  steps, distance, heart rate, sleep, active energy, VO2 max, etc. into a
  Health panel on the dashboard. It also imports real workout sessions if
  that export includes a `workouts` array.

## Getting started (local dev)

### 1. Database

You need a local PostgreSQL instance. If you don't have one:

```bash
sudo apt install postgresql
sudo service postgresql start
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'localdev';"
sudo -u postgres psql -c "CREATE DATABASE training_dashboard;"
```

### 2. Server

```bash
cd server
npm install
npx prisma migrate dev      # applies migrations to your local Postgres
npm run dev                 # starts the API on http://localhost:4000
```

`server/.env` holds `DATABASE_URL`, `JWT_SECRET`, and `SYNC_API_KEY` — change
the secrets before deploying anywhere real.

### 3. Client

```bash
cd client
npm install
npm run dev                 # starts the app on http://localhost:5173
```

The Vite dev server proxies `/api` requests to the backend, so just open
`http://localhost:5173` in a browser (or on your phone if it's on the same
network — use `npm run dev -- --host` for that).

### Installing on your phone

Once the app is deployed somewhere reachable from your phone, open it in
Chrome (Android) or Safari (iOS) and use "Add to Home Screen" — it installs
like a native app.

## Deployment (free, no credit card)

This repo includes a `render.yaml` Blueprint for [Render](https://render.com)
(free web service) paired with [Neon](https://neon.tech) (free Postgres,
never expires). Render's free web service spins down after 15 minutes of
inactivity and cold-starts in 30-60s on the next request — fine for a
personal dashboard, and irrelevant for the health sync since that runs on
its own schedule anyway.

1. Create a free Neon project at neon.tech and copy its connection string.
2. On Render: **New +** → **Blueprint** → connect this GitHub repo. Render
   reads `render.yaml` and provisions the web service automatically.
3. In the service's Environment tab, set `DATABASE_URL` to the Neon
   connection string (`JWT_SECRET` and `SYNC_API_KEY` are auto-generated by
   the blueprint).
4. Deploy. Render builds both `client` and `server` and serves the built
   client from the Express server — one service, one URL.
5. Open the deployed URL, register your account, and install it on your
   phone via "Add to Home Screen".

### Apple Health sync

The `SYNC_API_KEY` set on the deployed service authorizes
`POST /api/health/import`. Whatever runs the sync (a scheduled job, a
script) needs to fetch the latest Health Auto Export JSON from wherever
it's stored (e.g. Dropbox) and POST it as:

```json
{ "userEmail": "you@example.com", "files": [ /* one or more raw export files */ ] }
```

with header `x-sync-key: <SYNC_API_KEY>`.

## Production build (manual)

```bash
cd client && npm run build   # outputs static files to client/dist
cd server && npm run build && npm start   # runs migrations, serves client/dist + API
```
